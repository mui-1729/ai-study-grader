# 既存科目へ教材を追加する

`append:package` は新しい章・問題だけを既存科目へ追加するコマンドです。既存の章や問題の書き換え・削除・並べ替え、科目名・説明・採点方針の置換は行いません。新しい科目を作る場合は、通常の「教材を追加」を使います。

## 追加JSON

```json
{
  "schemaVersion": 1,
  "courseId": "sample-arithmetic",
  "version": "2",
  "chapters": [
    {
      "id": "ch-2",
      "title": "次の章",
      "content": "ここに新しい章の教材本文を記述します。"
    }
  ],
  "questions": []
}
```

- `courseId` は既存科目のIDです。ファイルは `data/courses/<courseId>.json` に存在する必要があります。
- `chapters` と `questions` の中身は、通常の [教材パッケージ形式](material-package.md) と同じです。
- 新規問題の所属章・復習先は、既存の章と今回追加する章を参照できます。
- `version` は追加後の版です。省略時は元の版と追加内容のハッシュから作成します。内容を追加する場合、元と同じ版は使えません。
- 同じIDですでに同じ内容がある場合は追加しません。同じIDで内容が違う場合は、その追加全体を拒否します。
- 章・問題・採点観点の重複、参照先の欠落、部分点の合計の不一致も拒否します。

## 1. 差分を確認する

```powershell
npm run append:package -- "C:\path\to\addition.json"
```

この段階では教材・履歴・下書き・設定を変更しません。追加する章ID、問題ID、すでに登録済みのID、更新前後の版、元ファイルの `baseFileHash` が表示されます。教材本文や回答は表示しません。

## 2. アプリを停止して適用する

起動しているアプリを、その端末で `Ctrl+C` により停止します。続けて、確認時のハッシュを指定します。

```powershell
npm run append:package -- "C:\path\to\addition.json" --apply --base-sha256 <表示されたbaseFileHash>
```

標準のポート4317以外で以前の版のアプリを使っている場合は、停止した上で、そのポートも `--port 4318` のように指定します。新しい版はデータフォルダーごとのロックも持つため、別ポートで動いていても更新を拒否します。ロック導入前の版では既定ポートと指定ポートを確認するため、独自ポートを省略しないでください。

適用処理は次を確認します。

1. 同じデータを使うアプリ・更新処理が動いていないこと。
2. 差分確認時から元の教材が変わっていないこと。
3. 個人用の `data/backups/<日時と識別子>/` に元の教材・マニフェストを保存し、履歴DBがあればSQLiteの整合性あるバックアップを作ること。WAL内の確定済みデータも含めます。
4. 既存章・問題が同じ内容で残り、下書きキーに使う問題オブジェクトも変わらないこと。
5. バックアップの内容とDBの整合性を確認し、保存直前にも教材・DBが変わっていないこと。
6. 新しいJSONを一時ファイルへ書き切ってから置き換えること。

この処理は履歴DBに書き込みません。既存の下書きと採点履歴は同じDBに残します。教材の版は更新し、今後の採点は新しい教材の版として記録します。過去の採点結果を採点し直したり上書きしたりしません。

同じ追加JSONを再適用すると、全内容が登録済みなら何も変更しません。教材の版も上げず、追加のバックアップも作りません。過去のハッシュを指定していても、同一内容の再適用は無変更で終了します。一部だけが登録済みの場合は、未登録分だけを追加する差分を改めて確認できます。

## 3. 自分で起動し直す

```powershell
npm run open
```

更新コマンド自身はアプリを起動せず、AIも呼び出しません。APIキーの保存ファイルは読み取りもバックアップもしません。バックアップには個人教材と履歴が含まれるため、公開GitHubや配布ZIPには含めません。

アプリは起動時に教材を読み込むため、起動中にJSONだけを手で書き換えないでください。元の問題を改題・修正したい場合は、この追加コマンドでは扱わず、別の改訂手順として確認します。
