# 元資料から学習を始めるまで

## 推奨する流れ

1. 元の講義資料・教科書・ノートと、`docs/create-material-prompt.md` のプロンプト本文を、教材作成を任せるAIに渡す。
2. AIから、教材本文・問題・模範解答・採点基準・復習先を含む `course-....json` と、作成確認レポートを受け取る。
3. レポートで読めた範囲・未確認箇所を見て、問題と解答の一部を元資料と照合する。
4. `npm run validate:package -- "C:\path\to\course.json"` で形式を確認する。この操作は教材の追加やAI接続を行わない。
5. アプリの「教材を追加」からJSONを選び、読む・解く・採点・復習を始める。

形式検証はJSONの構造・配点・参照先を確認するもので、内容の正しさや出典の実在を保証しない。問題・模範解答・部分点の妥当性も確認する。

## 元資料はアプリにも追加するべきか

学習・採点に必須なのは完成した教材パッケージである。元資料は、手元に保存して照合できればよく、毎回アプリへ重ねて入れる必要はない。

元の文章もアプリで読みたい場合は、PDF・Markdown・テキストとして別の教材に追加できる。ただし、現在は**別教材同士を自動的に関連付けず、採点時に他の教材を横断検索しない**。元PDFを別に追加しても、生成した問題の採点根拠が自動で増えるわけではない。

AI採点に使われるのは、同じパッケージ内の問題・模範解答・採点基準・指定された復習章の抜粋である。したがって、生成パッケージ内に必要な定義や条件を含め、章本文に元ファイル名・ページ等の参照先を残す。元資料が図表中心なら、図表が正しく説明へ反映されているかも確認する。

## 作成もアプリへ入れるべきか

最初の運用では、外部AIでの作成とアプリでの学習を分ける構成が扱いやすい。元資料に対する追加指示や訂正を対話で行え、長いPDFや図・数式を扱う作成処理と、毎回の採点の利用枠を分けて管理できる。ただし、外部AIなら全ての資料を正しく読めるという保証はない。

同じ形式の資料から何度も作成し、修正や取り込みが手間になった時点で、アプリ内に「資料解析 → 範囲の確認 → 教材・問題の下書き → 人が確認 → 登録」を追加するとよい。自動作成は、単にAIを1回呼ぶだけではなく、読み取り確認、長い資料の分割、出典対応、解答と基準の検証、失敗時の扱いが必要になる。

現在のアプリには、元資料からまとめ・テストを自動生成する機能は含めていない。INIAD AI-MOPを作成にも使う場合は、その処理も同じサービスの利用枠に計上され得る。現時点で確認できていないモデル別換算や日次上限を仮定しない。
