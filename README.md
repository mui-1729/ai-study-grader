# Study Studio

自分の教材で「読む → 解く → 採点と解説 → 復習」を繰り返す、日本語の個人用学習アプリです。教材は科目別のパッケージとして追加でき、アプリ本体を編集せずに切り替えられます。

## できること

- PDF・Markdown・UTF-8テキストを、画面の「教材を追加」から登録・閲覧。
- 問題・模範解答・採点基準を含むJSONパッケージを取り込み。
- 問題の手動追加、回答の下書き保存、INIAD AI-MOPによる記述採点。
- 部分点・回答の引用・誤答理由・模範解答・教材の復習先を表示。
- 厳密一致問題の通常採点、API未設定時の自己採点。
- 学習履歴、要復習の絞り込み、解き直し。
- 日次のAPI使用量・採点回数と、対話のquotaで最後に確認した残量の記録。
- 「教材を追加」画面から、教材作成用プロンプトのコピー・全文表示・ダウンロード。

初期版は自分のパソコン専用です。サーバーは `127.0.0.1` にのみ接続を許可します。ログインや複数人のデータ分離はありません。公開サーバーへそのまま配置しないでください。

## 起動

Node.js 24以上が必要です。アプリのフォルダーで次を実行します。

```powershell
npm ci
npm run build
npm start
```

準備済みなら、PowerShellでアプリのフォルダーに移動して次を実行すると、通常使っているブラウザーで開きます。

```powershell
cd "C:\path\to\study-studio"
npm run open
```

別の場所へ移した場合は `cd` のパスを変更してください。`npm run open` は変更を反映するためのビルドも実行します。終了はそのPowerShellで `Ctrl+C`。ブラウザーを自動で開かず起動する場合は `npm start`、ソース変更後は先に `npm run build` を実行します。

ブラウザーで [Study Studio](http://127.0.0.1:4317) を開きます。停止は実行中の画面で `Ctrl+C`。開発時も編集後に `npm run build` を実行し、サーバーと画面を再読み込みします。

最初の教材として、`examples/sample-course.json` を「教材を追加」から選べます。個人の教材はリポジトリに含めていません。

## INIAD AI-MOPの設定

1. ご自身でAI-MOPのAPIキーを取得します。キーをこのチャットやGitHubへ貼らないでください。
2. ローカルのアプリで「AIの設定」を開き、パスワード欄へキーを入力して保存します。
3. 「利用できるモデルを確認」で接続と正式なモデルIDを確認します。モデル一覧APIが提供されない場合は、AI-MOPで案内されるIDを直接入力します。

標準は `gpt-6-luna`。問題の採点画面で必要なときだけ `gpt-6-astra` を選べます。これらのIDがAI-MOPの利用アカウントで提供されるかは接続して確認してください。モデル一覧取得は生成を行いませんが、サービス側のリクエスト制限の対象になる可能性があります。

画面からの設定は `data/ai-config.json` にローカル保存します。このファイルは鍵を含み、暗号化されていません。共有端末ではOSの利用者アカウントを分けてください。`.env.example` を `.env` にコピーし、`INIAD_API_KEY` と `INIAD_MODEL` を設定する方法もあります。画面で保存した設定がある場合はそちらを優先します。端末で非表示入力するには `npm run setup:ai` を実行してからアプリを再起動します。

接続先はユーザー提供の利用ガイドに合わせた `https://api.openai.iniad.org/api/v1/chat/completions` に固定し、OpenAI本家や別のプロバイダーへ自動で切り替えることはありません。AI SDKのChat Completions互換プロバイダーを使用し、未確認のStructured Outputsパラメーターやツールは送りません。返されたJSONはアプリ側で検証します。

### 利用枠への配慮

- 1問につき1回の呼び出し。エラーや制限時の自動再送は0回。
- 過去の会話や履歴を送らず、今回の回答と問題・模範解答・採点基準・関連する本文だけを送信。
- 補助教材は1章最大8,000文字、合計12,000文字まで。省略の有無もAIへ伝えます。
- 出力上限4,096トークン、タイムアウト90秒、同時採点1件。出力不足や不正な引用はエラーにし、点数を作りません。
- Lunaでの採点後にAstraを選んで再採点すると、別の呼び出しとして履歴に残ります。

「利用状況」には、日本時間の日付ごとに、このアプリの採点要求回数とAPIが返した入力・出力・合計トークン数を表示します。失敗した処理も要求回数に含め、トークン数が返らなかった処理は未報告として区別します。採点結果が無効でも、APIが返した使用量は残します。

対話画面の `quota` で確認した日次残量を、確認時刻とともに手動で記録できます。これはライブ取得した残量でも毎日の固定上限でもありません。翌日には前日の確認値と表示し、自動で補充しません。Slackなど他の利用やモデル別の換算方法が未確認のため、このアプリの使用量を単純に引いて現在残量とは表示しません。API応答に制限ヘッダーがあれば、応答時刻・モデルと一緒に別枠へ記録します。短時間の制限と日次quotaの同一性や共有範囲は未確認です。

対話の `quota` はAI-MOP側のコマンドの可能性があり、採点用モデルへ文字列として送信して残量を尋ねる処理は行いません。残量を取得する公式APIはまだ確認できていません。実際の残量はAI-MOP側で確認してください。

## 教材の追加・差し替え

### 本文のファイル

PDF、`.md`、`.txt` を「教材を追加」で選びます。PDFは最大150ページ、ファイルは15MBまで、抽出本文は500,000文字までです。元ファイルを変更せず、抽出した本文だけを保存します。本文だけを登録した段階では問題は0件です。「確認テスト → 問題・解答を追加」で追加できます。

PDFの図、画像だけのページ、数式のレイアウト、読み順は保証しません。本文が抽出できない場合はエラーを表示します。OCRや動画・手書き回答は初期版の対象外です。登録後に本文を確認してください。

### 問題付き教材パッケージ

登録済みの同じ科目へ新しい章・問題を足す場合は、[追加専用の更新手順](docs/append-package.md) を使えます。まず `npm run append:package -- "追加.json"` で差分だけ確認し、停止後に確認した元ファイルのハッシュを指定して適用します。既存内容の書き換えは拒否し、教材と履歴DBを個人用フォルダーへバックアップします。

他のAIへ元資料を渡して教材を作る場合は、[教材作成用プロンプト](docs/create-material-prompt.md) をそのまま使えます。[元資料から学習までの手順](docs/material-workflow.md) に、元資料をアプリへ入れる場合の扱いと、アプリ内自動作成との使い分けをまとめています。

取り込み前に、ファイルを追加せず形式だけ確認することもできます。

```powershell
npm run validate:package -- "C:\path\to\course.json"
```

`examples/sample-course.json` と [教材パッケージ形式](docs/material-package.md) を参照してください。まとめ・問題・解答をこのチャットなどで作成し、同じ形式のJSONにすれば、ファイル選択1回で追加できます。同じIDの重複は上書きせず拒否します。別の教材・改訂版は別のIDで追加してください。

コマンドからも追加できます。

```powershell
npm run import:package -- "C:\path\to\my-course.json"
```

専用変換スクリプト `scripts/import-course.ts` は、別途作成した4本の教材原稿を読み込みます。原稿を持つ利用者が次を実行すると、11章・確認44問・模試大問7題（100点）を検証して登録します。元ファイルを編集・削除しません。ファイル名はスクリプトを参照してください。登録後にアプリを再起動します。

```powershell
npm run import:course -- "C:\path\to\教材原稿"
```

取り込み直後の教材には、原稿由来の採点基準をそのまま含めます。確認テストは全体を1観点として原稿の配点を計算し、模試は小問ごとの観点に分けます。AIの実際の採点品質は、正解・部分正解・別解・誤答の答案で追加評価が必要です。

## データとGitHub

| 保存場所                                         | 内容                     | Git管理 |
| ------------------------------------------------ | ------------------------ | ------- |
| `src/`, `public/`, `scripts/`, `tests/`, `docs/` | アプリとドキュメント     | 対象    |
| `examples/`                                      | 自作の公開可能なサンプル | 対象    |
| `data/courses/`                                  | 個人の教材・問題・解答   | 対象外  |
| `data/study.sqlite*`                             | 回答・下書き・履歴       | 対象外  |
| `data/ai-config.json`, `.env`                    | APIキーなど              | 対象外  |
| `work/`, `outputs/`, `node_modules/`, `dist/`    | 作業・配布・生成ファイル | 対象外  |

バックアップは、停止中に `data/` を個人用の安全な場所へコピーします。鍵も含まれるため、公開フォルダーや公開ZIPへ入れないでください。履歴はSQLiteで永続化し、画面には最新2,000件を表示します。履歴には問題の模範解答・基準・教材バージョンと内容ハッシュも残り、後の教材追加で過去の採点結果を書き換えません。

GitHubにはコードだけを上げます。アップロード前に `git status` と `git diff --cached` を確認し、`data/`・鍵・個人教材・回答が含まれていないことを確認してください。リポジトリの作成先・名前・公開範囲は利用者が決めてから設定します。

## 採点の安全性と限界

教材や回答はJSON引用データとして分離し、採点者への指示とは別のメッセージに置きます。ツール・コード実行・外部検索は与えず、AIに鍵を渡しません。点数は観点ごとの上限とIDの一致を検証し、合計をサーバーで計算します。回答の引用が実在することも検証し、加点には引用を要求します。UIはMarkdownの危険なHTMLと外部画像を取り除きます。ローカルAPIにはHost・Origin・トークンの検証を設けています。

これらはAIが必ず正しく採点する保証ではありません。資料や回答に埋められた指示への耐性、部分点の妥当性、別解の評価は実モデルでの追加確認が必要です。AIの回答は学習の補助として、基準と根拠を見比べて使います。

## 開発と確認

### 採点エラーを確認するとき

数式や複数行の答案の根拠は、AIが指定した回答の行番号を検証し、アプリが元の回答から引用します。AIに数式を長く書き写させる必要はありません。存在しない行番号・重複した行番号・配点や観点の不一致は、そのまま採点済みとして扱わず拒否します。旧形式の文字列引用を返す応答も、回答内に完全一致する引用がある場合に限り受け付けます。

返答の形式不正、出力上限、採点観点・根拠行の不一致は、接続や利用枠のエラーと区別して表示します。エラーは問題画面にも残し、点数を記録せず回答の下書きを維持します。利用記録には失敗の種類と対象の問題IDを残し、APIキーや応答本文は記録しません。自動再送はしません。

起動後に設定ファイルからキーを削除しても、起動中のプロセスは読み込んだ設定を保持します。再起動すると保存済みの設定を読み直します。設定ファイルのキーが空なら、再起動後にアプリの設定画面でキーを入力してください。

```powershell
npm run check
npm test
npm run build
```

テストは実APIキーを使いません。AI-MOPの接続形式は模擬応答で確認します。実際の鍵・提供モデル・利用枠・採点品質は、利用者の設定後に確認する必要があります。テスト用データは `work/tests/` に作り、個人データは使用しません。

初期版に含めない機能：資料からまとめ・テストを自動作成する処理、追加質問チャット、手書き/OCR、動画取り込み、60分の一括受験・タイマー、公開共有・利用者認証。まず作成済み教材を取り込み、学習と採点を使う構成です。

参考：[AI SDKのOpenAI互換接続](https://ai-sdk.dev/providers/ai-sdk-providers/openai)、[OpenAIの安全性ガイド](https://developers.openai.com/api/docs/guides/safety-best-practices)、[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)。AI-MOP固有の接続方法はユーザー提供の利用ガイドを確認しました。ガイドにある古いモデル名・数値上限を現在の仕様とは見なしていません。
